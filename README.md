# MediCare — კლინიკის ჩაწერის სისტემა (Clinic Appointment System)

საბაკალავრო პრაქტიკული პროექტი. სრულფასოვანი ვებ-აპლიკაცია პაციენტების,
ექიმებისა და ადმინისტრატორისთვის — სამედიცინო ვიზიტების დაჯავშნისთვის,
მართვისა და ანალიტიკისთვის.

## ფუნქციონალი

### ავთენტიფიკაცია და პროფილი
- სამი როლი — პაციენტი, ექიმი, ადმინისტრატორი — JWT-ავთენტიფიკაციით
- რეგისტრაცია (ელ-ფოსტისა და ტელეფონის უნიკალურობის შემოწმებით)
- პროფილის რედაქტირება (სახელი, ტელეფონი, პაროლის შეცვლა)
- პაროლის აღდგენა (სიმულირებული email-ნაკადი — იხ. "ცნობილი შეზღუდვები")
- მუქი/ღია თემა (dark mode), შენახული მომხმარებლის მოწყობილობაზე

### ჯავშნის სისტემა
- სლოტების ავტომატური გენერაცია ექიმის სამუშაო საათებისა და სლოტის
  ხანგრძლივობის მიხედვით
- კონფლიქტების თავიდან აცილება — ორი პაციენტი ერთსა და იმავე დროის
  სლოტზე ვერ ჩაიწერება (409 Conflict)
- ჯავშნის გადატანა (reschedule) და გაუქმება
- ჯავშნის გაკეთება ოჯახის წევრისთვისაც (არა მხოლოდ საკუთარი თავისთვის)
- საქართველოს სახელმწიფო/რელიგიური უქმე დღეების კალენდარი (მათ შორის
  მართლმადიდებლური აღდგომის ციკლი გამოთვლილია ალგორითმულად) — ამ დღეებზე
  ჯავშნის გაკეთება სერვერის მხარეს იბლოკება
- ექიმის ინდივიდუალური დასვენების დღეები (time off)

### ექიმის დაშბორდი
- ვიზიტების ცხრილი და კვირის კალენდარული ხედი (urgency-ბეჯებით)
- საკუთარი განრიგის მართვა (სამუშაო საათები, სლოტის ხანგრძლივობა)
- რეცეპტის/დიაგნოზის გამოწერა — ავტომატურად ასრულებს ვიზიტს
- რეცეპტის PDF გენერაცია ქართული ფონტის embedding-ით (Noto Sans Georgian)

### პაციენტის დაშბორდი
- სამედიცინო ისტორია (timeline ფორმატში, დიაგნოზი+რეცეპტით)
- ექიმის შეფასება 1-5 ვარსკვლავით დასრულებული ვიზიტის შემდეგ — საშუალო
  შეფასება ავტომატურად ჩანს ექიმის ბარათზე
- რჩეული ექიმების სია
- ოჯახის წევრების მართვა

### შეტყობინებები
- in-app შეტყობინებები (ჯავშნის დადასტურება/გაუქმება/რეცეპტი/შეფასება)
- ვიზიტამდე 24-საათიანი შეხსენების სიმულაცია

### AI-ფუნქციები (rule-based, გამჭვირვალე — არა შავი ყუთი)
- **სიმპტომების ანალიზი** — keyword-scoring მოდელი წონიანი საკვანძო
  სიტყვებით, რომელიც განსაზღვრავს სამედიცინო სპეციალობასა და
  სანდოობის ქულას
- **გადაუდებლობის შეფასება (triage)** — ცალკე ლექსიკონი, რომელიც
  გამოავლენს გადაუდებელი/სასწრაფო მდგომარეობის ნიშნებს
- **ჭკვიანი ექიმის რანჟირება** — რეკომენდებული ექიმები ლაგდება
  რეიტინგის, გამოცდილებისა და ფასის კომბინირებული ქულით
- **შეფასებების სენტიმენტ-ანალიზი** — lexicon-based დადებითი/ნეიტრალური/
  უარყოფითი კლასიფიკაცია ადმინის დაშბორდისთვის
- **სხეულის რუკა** — ინტერაქტიული SVG, სიმპტომის სწრაფად შესარჩევად
- გარე საჯარო API-ების ინტეგრაცია (Open-Meteo, key-ის გარეშე):
  დღის ჯანმრთელობის რჩევა (ამინდზე დაფუძნებული) და თბილისის ჰაერის
  ხარისხის ინდექსი (AQI)

### ადმინის დაშბორდი
- ანალიტიკა: მომხმარებლები, ჯავშნები სპეციალობის მიხედვით, ბოლო 7 დღის
  აქტივობა და შემოსავალი, პლატფორმის საშუალო რეიტინგი
- ბოლო აქტივობის ცოცხალი feed
- ტოპ ექიმების leaderboard
- ექიმების სრული CRUD (დამატება/რედაქტირება/დეაქტივაცია)
- მომხმარებლების ძებნა/ფილტრაცია და დეაქტივაცია/გააქტიურება
- სისტემის მდგომარეობის პანელი (ჰაერის ხარისხი, უახლოესი უქმე დღეები)

### REST API
სრული დოკუმენტაცია (Swagger/OpenAPI) ხელმისაწვდომია `/docs` მისამართზე
გაშვების შემდეგ.

## ტექნოლოგიური სტეკი

| ფენა | ტექნოლოგია |
|---|---|
| Backend | Python 3.12, FastAPI |
| ORM / DB | SQLAlchemy + SQLite |
| ავთენტიფიკაცია | JWT (python-jose) + bcrypt (passlib) |
| PDF | ReportLab + ჩაშენებული Noto Sans Georgian ფონტი |
| გარე API | Open-Meteo (ამინდი/ჰაერის ხარისხი), httpx კლიენტი |
| Frontend | HTML, Tailwind CSS (CDN), Chart.js, Vanilla JavaScript (SPA) |

Frontend დაწერილია React/build-tool-ის გარეშე განზრახ — ერთი `index.html`
ფაილია, რომელსაც პირდაპირ ბექენდი გვთავაზობს (`StaticFiles`), ასე რომ
დამატებითი `npm install` საჭირო არ არის. ყველა ხატულა inline SVG-ია
(არა გარე icon-CDN), ავატარები გენერირებულია SVG-ინიციალებად — გვერდი
სრულად იტვირთება ერთი გარე ქსელური მოთხოვნის გარეშეც (Tailwind/Chart.js/
Google Fonts CDN-ების გარდა).

## გაშვება ლოკალურად

**წინაპირობა:** დაინსტალირებული უნდა გქონდეთ Python 3.10 ან უფრო ახალი.

```bash
# 1. გადადით backend საქაღალდეში
cd clinic-appointment-system/backend

# 2. შექმენით ვირტუალური გარემო (რეკომენდებულია)
python -m venv venv
source venv/bin/activate        # Windows-ზე: venv\Scripts\activate

# 3. დააინსტალირეთ დამოკიდებულებები
pip install -r requirements.txt

# 4. შექმენით საწყისი დემო-მონაცემები (ადმინი, 39 ექიმი 9 სპეციალობაზე, პაციენტი)
python seed.py

# 5. გაუშვით სერვერი
uvicorn main:app --reload
```

სერვერის გაშვების შემდეგ გახსენით ბრაუზერში:

- **საიტი**: http://localhost:8000
- **API დოკუმენტაცია (Swagger)**: http://localhost:8000/docs

## სატესტო ანგარიშები (`seed.py`-ის შემდეგ)

| როლი | ელ-ფოსტა | პაროლი |
|---|---|---|
| ადმინი | admin@clinic.ge | admin123 |
| პაციენტი | patient@clinic.ge | patient123 |
| ექიმი (მაგ. კარდიოლოგი) | cardio@clinic.ge | doctor123 |

`seed.py` ქმნის 39 ექიმს 9 სამედიცინო სპეციალობაზე (4-5 ექიმი თითოზე,
სხვადასხვა ფასითა და გამოცდილებით — `doctor123` პაროლით ყველასთვის,
სრული სია ფაილშივეა), რომ ძებნა/ფილტრაცია ფასისა და გამოცდილების
მიხედვით რეალურად საჩვენებელი იყოს.

## დაჰოსტვა

ყველაზე მარტივი გზა — **Render.com** ან **Railway.app**-ის უფასო ტარიფი:

1. აიტვირთეთ `backend/` საქაღალდის შემცველობა GitHub რეპოზიტორიზე
2. Render/Railway-ზე შექმენით ახალი "Web Service"
3. Build command: `pip install -r requirements.txt && python seed.py`
4. Start command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
5. რამდენიმე წუთში მიიღებთ საჯარო ბმულს (მაგ. `https://your-app.onrender.com`)

ვინაიდან frontend-ი (`index.html`) ბექენდის მიერვეა serve-ული
(`StaticFiles`), ერთი დეპლოი საკმარისია მთელი პროექტისთვის.

## აკადემიური ნაშრომისთვის გამოსადეგი ტექნიკური დეტალები

- **მონაცემთა ბაზის დიაგრამა**: `models.py`-ში 13 ცხრილია
  (`users`, `doctor_profiles`, `appointments`, `prescriptions`,
  `doctor_reviews`, `doctor_time_off`, `password_reset_tokens`,
  `notifications`, `favorite_doctors`, `family_members` და სხვ.)
  ერთმანეთთან დაკავშირებული foreign key-ებით — გამოსადეგია ER-დიაგრამის
  დასახატად.
- **API-ის სრული სია** ავტომატურად ჩანს `/docs`-ზე (Swagger UI).
- **უსაფრთხოება**: პაროლები ინახება bcrypt-ჰეშით, API endpoint-ები
  დაცულია JWT-ტოკენით და როლზე დაფუძნებული წვდომის კონტროლით (RBAC),
  password-reset ნაკადი არ ამხელს რომელი ანგარიშები არსებობს
  (user-enumeration-ის თავიდან აცილება).
- **ტესტირებისთვის**: სცადეთ ორი პაციენტის ანგარიშით ერთსა და იმავე
  დროის სლოტზე ჯავშნის გაკეთება — მეორე მცდელობა სისტემამ უნდა დაბლოკოს
  (409 Conflict) — კარგი მაგალითია "ტესტირება და შედეგები" თავისთვის.

## ცნობილი შეზღუდვები (გამჭვირვალობისთვის)

- ეს არის სასწავლო/დემო პროექტი: რეალური გადახდები არ არის ინტეგრირებული.
- SMS/Email შეტყობინებები **სიმულირებულია** (in-app შეტყობინებები და
  პაროლის აღდგენის ტოკენი პირდაპირ ეკრანზე ჩანს, ნაცვლად რეალური
  გაგზავნისა) — რეალურ სისტემაში დაემატებოდა Twilio/SendGrid-ის მსგავსი
  სერვისი.
- AI რეკომენდაცია და გადაუდებლობის შეფასება არის მარტივი, გამჭვირვალე
  keyword-matching მოდელები და არა კლინიკური დიაგნოსტიკური ინსტრუმენტი —
  ეს მკაფიოდ არის აღნიშნული ინტერფეისშიც.
- ვიზიტის "დასრულებული" სტატუსი დროზე დაფუძნებულად ავტომატურად არ
  გენერირდება — მხოლოდ მაშინ იცვლება, როცა ექიმი რეალურად ჩაწერს
  დიაგნოზს/რეცეპტს (მონაცემთა სისწორის უზრუნველსაყოფად).
